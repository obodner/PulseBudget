## 1. תקציר מנהלים וחזון המוצר (Executive Summary & Vision)

**PulseBudget** היא אפליקציית רשת (Web Application) בזמן אמת לניהול תקציב, הוצאות ותזרים מזומנים אישי ומשפחתי, הבנויה סביב הרעיון המהפכני של **"מד צעדים פיננסי" (Financial Pedometer)**.

כשם שצמידי כושר ושעונים חכמים מנטרים צעדים ודופק לאורך היום ומעניקים משוב מיידי שמניע הרגלי תנועה בריאים, PulseBudget מספקת לולאת משוב שוטפת ורציפה על קצב שריפת הכסף ועל עמידה ביעדי התקציב היומי, השבועי והחודשי. באמצעות ניטור "הדופק הפיננסי" בכל רגע נתון, המשתמש נמנע מהפתעות בסוף החודש ושומר על משמעת כלכלית באמצעות חוויית משתמש קלילה, מעוצבת ומתגמלת.

## 2. המוטיבציה והגדרת הבעיה (Motivation & Problem Statement)

### 2.1 הכשלים באפליקציות תקציב מסורתיות
- **מודעות מאוחרת ("בדיעבד" / Post-Mortem):** רוב המשתמשים מגלים שחרגו מהתקציב רק כאשר פירוט כרטיס האשראי מגיע בסוף החודש – זמן רב לאחר שההוצאות כבר בוצעו ואין דרך לתקנן.
- **סרבול וטפסים מעיקים:** אפליקציות תקציב מורכבות מחייבות התאמות חשבון מרובות, שדות אינסופיים והבנה חשבונאית, מה שמוביל לנטישה המונית של משתמשים כבר בשבועיים הראשונים.
- **היעדר תמונת קצב בזמן אמת:** אפליקציות קלאסיות מציגות סכום מצטבר יבש (למשל: "הוצאת החודש ₪6,300"), אך אינן עונות על השאלה היומיומית הקריטית: *"האם אני יכול להרשות לעצמי לצאת הערב למסעדה ב-₪200 מבלי לחרוג מהיעד החודשי שלי?"*
- **ערבוב מטעה בין הכנסות להוצאות:** פלטפורמות רבות מקזזות הוצאות ישירות מסך ההכנסות, מה שיוצר אשליה מסוכנת שבה כניסה של הכנסה חד-פעמית גדולה (מענק, בונוס, משכורת) מטשטשת הרגלי בזבוז יומיים בלתי מרוסנים.

### 2.2 הפתרון של PulseBudget
- **פרדיגמת "מד הצעדים":** התייחסות לתקרות התקציב כאל מכסת צעדים יומית, שבועית וחודשית. כל הוצאה מקדמת את טבעת ההתקדמות הזוהרת.
- **בדיקת דופק באפס שניות:** מבט חטוף במסך הראשי מציג מיד האם ההוצאה נמצאת בטווח **בטוח (טורקיז)**, ב**התראה (כתום)**, או ב**חריגה (אדום)**.
- **הפרדה מוחלטת: תקרות חלות אך ורק על הוצאות:** גבולות התקציב מיועדים לבלימת הוצאות בלבד. הכנסות מתועדות במדויק עבור מעקב תזרים ומאזן נטו, אך אינן מגדילות או מנפחות את תקרת ההוצאות.
- **משחוק ויזואלי וקולי (Gamification):** שילוב מנוע סאונד מובנה של משחקי Super Mario ברטרו-שיק (צליל מטבע בעת רישום מוצלח, צליל אזהרה וחריגה בעת שבירת תקרה), ההופך את המעקב הפיננסי לשגרה מהנה וחיובית.

## 4. עקרונות מוצר ולוגיקה עסקית-פיננסית (Business Logic)

### 4.1 כלל הברזל: תקרות מיועדות אך ורק להוצאות
> **כלל מרכזי:** *התקרות (תקציב יומי, שבועי וחודשי) וטבעת היעד חלות אך ורק על הוצאות (Expenses).*

- **הוצאות (Expenses):** נספרות אל מול התקרה, ממלאות את טבעת הפעימה, ומפעילות מצבי התראה וחריגה.
- **הכנסות (Income):** מתועדות לצורך מדדי תזרים (`metricIncValue`), רווח/מאזן נטו (`metricNetValue`), ולשונית הכנסות – אך **אינן** מגדילות את התקרה שנותרה ואינן מוחקות חריגות בהוצאות.

### 4.2 מדרגות סטטוס וקוד צבעים (Thresholds & Visual Signals)
- **מצב בטוח (Safe State - אחוז צריכה קטן מ-80%):**
  - צבע מוביל: `#00F5D4` (טורקיז ניאון)
  - תיאור קצב: "בקצב תקין ומאוזן"
- **מצב אזהרה (Warning State - בין 80% ל-100%):**
  - צבע מוביל: `#F59E0B` (כתום/זהב התראה)
  - תיאור קצב: "קצב צריכה מואץ - תשומת לב"
  - משוב קולי: צליל התראה רטרו נמוך (Mario Bump)
- **מצב חריגה (Danger / Over-Cap - מעל 100% מהתקרה):**
  - צבע מוביל: `#EF4444` (אדום חריגה בוהק)
  - תיאור קצב: "חריגה מתקרת התקציב!"
  - משוב קולי: מנגינת אזהרה / Game Over של מריו, הבהוב פעימה אדום של הטבעת הראשית.

### 4.3 נוסחאות חישוב קצב ומאזן
עבור כל תקופה נבחרת:
$$\text{אחוז ניצול התקציב} = \left( \frac{\text{סך הוצאות לתקופה}}{\text{תקרת התקציב לתקופה}} \right) \times 100$$
$$\text{יתרה לתקופה} = \max(0, \text{תקרת התקציב לתקופה} - \text{סך הוצאות לתקופה})$$
$$\text{מאזן נטו} = \text{סך הכנסות לתקופה} - \text{סך הוצאות לתקופה}$$

## 5. דרישות פונקציונליות (Functional Requirements)

### 5.1 אימות משתמשים וסנכרון ענן (FR-AUTH)
- **FR-AUTH-1 (התחברות באמצעות גוגל):** כניסה בלחיצה אחת עם חשבון Google דרך חלונית קופצת (Popup) עם תמיכה בבחירת חשבונות (`select_account`).
- **FR-AUTH-2 (דוא"ל וסיסמה):** תמיכה מלאה בהרשמה והתחברות באמצעות כתובת אימייל וסיסמה עם ולידציה.
- **FR-AUTH-3 (מצב אורח ועבודה לא-מקוונת):** שימוש מלא ב-`localStorage` של הדפדפן בהיעדר חיבור לרשת או לפני התחברות לחשבון.
- **FR-AUTH-4 (סנכרון בזמן אמת ב-Firestore):** סנכרון דו-כיווני מיידי עם מסד הנתונים בענן ברגע שמשתמש מחובר, כולל האזנה לשינויים (`onSnapshot`).
- **FR-AUTH-5 (ניהול פרופיל):** הצגת תמונת משתמש/אוואטר, כתובת הדוא"ל, סטטוס סנכרון וכפתור התנתקות מאובטחת.
- **FR-AUTH-6 (עריכת שם תצוגה אישי בפרופיל - FR-PROFILE-NAME):**
  - **התאמה אישית:** מתן אפשרות למשתמש לערוך ולשנות את שם התצוגה שלו בכל עת ישירות מתפריט הפרופיל, הן באמצעות כפתור עפרון ייעודי בראש החלון והן מתוך פריט תפריט מוגדר.
  - **דיאלוג עריכה וולידציה:** פתיחת חלונית מודאל ייעודית עם שדה קלט ממוקד, כולל ולידציית תקינות (שם לא ריק, אורך בין 1 ל-50 תווים, קיצוץ רווחים מיותרים).
  - **שמירה רב-שכבתית:** סנכרון מיידי לפרופיל המשתמש ב-Firebase Auth (`updateProfile`), למסמך המשתמש בענן Firestore (`users/{uid}`), ובזיכרון המקומי בדפדפן (`localStorage`) לתמיכה מלאה במצב אורח ולא-מקוון.
  - **משוב מיידי:** עדכון מיידי של אות האוואטר, שמות התצוגה בממשק, צליל הצלחה 8-bit רטרו (Mario 1-UP) והקפצת הודעת Toast לאישור.

### 5.2 ניהול תקרות תקציב (FR-CAPS)
- **FR-CAPS-1 (שלוש רמות תקרה):** אפשרות להגדרה ועריכה של תקרה **יומית**, **שבועית** ו**חודשית** בשקלים חדשים (₪).
- **FR-CAPS-2 (אשף הגדרה ראשונית):** במידה והתקרות טרם הוגדרו, המערכת מציגה חלון ייעודי המנחה את המשתמש לקביעת יעדיו הראשונים.
- **FR-CAPS-3 (חישוב מחדש מיידי):** עדכון התקרות מביא לעדכון חי ומיידי של טבעת היעד, קווי התקרה בגרפים והיתרות הנותרות, ללא צורך בריענון הדף.

#### 5.2.1 ניהול תקרות תקציב לפי קטגוריה (FR-CATEGORY-CAPS)

##### 1. תיאור כללי ועקרונות ליבה
- **הרחבת מנגנון התקרות:** הרחבת יכולת הגדרת התקרות הקיימת (יומית, שבועית, חודשית) כך שתתאפשר הגדרה ברמת קטגוריית הוצאה בודדת בנוסף לתקרה הכללית.
- **חלות על הוצאות בלבד:** בהתאם לכלל הברזל של המערכת, תקרות קטגוריאליות חלות אך ורק על תנועות מסוג הוצאה (`expense`).

##### 2. היררכיה ולוגיקת קטגוריית "כללי" (Umbrella Budget)
- **תקרת מטריה כוללת:** קטגוריית "כללי" מתפקדת כתקרת-על עבור כלל ההוצאות במערכת.
- **אכיפת גבול עליון:** תקרה מוגדרת בקטגוריה ספציפית (יומית, שבועית או חודשית) אינה יכולה לחרוג מערך התקרה המקבילה שהוגדרה ב"כללי".
- **תלויות ועדכון:** בעת הקלדת או עדכון תקרה לקטגוריה, המערכת תבצע ולידציה מיידית:
  - אם `CategoryCap > GeneralCap`, המערכת תחסום את השמירה ותציג חיווי שגיאה מתאים.
  - הפחתת תקרת ה"כללי" מתחת לתקרה קיימת של אחת הקטגוריות תחייב התאמה או עדכון מונחה למשתמש.

##### 3. כללי ולידציה ומינימום הגדרות
- **חובת הגדרה מינימלית:** כדי לשמור על תקינות "מד הצעדים הפיננסי", המערכת תחייב קיומה של לפחות הגבלה תקפה אחת (יומית, שבועית או חודשית) באחת מקטגוריות ההוצאה או ב"כללי".
- **מניעת ערכים ריקים:** לא תתאפשר שמירת מסך התקרות ללא עמידה בתנאי סף זה.

##### 4. ממשק משתמש – חלון "תקרות" (UI/UX)
- **תצוגה מרוכזת ושקופה:** מודאל/מסך התקרות יציג רשימה מאוחדת וסריקה של כל קטגוריות ההוצאה המובנות (כולל האייקונים הקיימים: מזון, תחבורה, פנאי וכו') לצד קטגוריית "כללי".
- **עריכה וסקירה:**
  - לכל קטגוריה יוצגו שדות קלט ייעודיים לתקרה יומית, שבועית וחודשית (₪).
  - אינדיקטור ויזואלי ברור עבור קטגוריות שבהן הוגדרה תקרה לעומת קטגוריות ללא הגבלה פעילה.
  - הצגת חסם ה"כללי" בזמן אמת בסמוך לשדות הקלט של הקטגוריות הפרטניות.

##### 5. מנגנון התראות על חריגה מתקרות קטגוריה (Breach Notifications)
- **התראה קופצת מיידית (In-App Toast Notification):** ברגע שהזנת הוצאה חדשה גורמת לקטגוריה לחרוג מתקרתה (יומית, שבועית או חודשית), המערכת מקפיצה מיידית חלונית התראה צפה זוהרת בחלק העליון של המסך עם פירוט הסכום שנוצל, התקרה וגובה החריגה.
- **משוב קולי ורטט (Audio & Haptic Feedback):** השמעת צליל אזהרה של Super Mario (`playMarioGameOver`) והפעלת רטט haptic במכשירים ניידים נתמכים.
- **התראות דפדפן (Web Notifications API):** שליחת התראת מערכת ייעודית של הדפדפן (בכפוף לאישור המשתמש).
- **חיווי בבאנר הראשי (Dashboard Banner):** באנר ההתראות הראשי במסך הבית מציג באופן ברור את רשימת הקטגוריות החורגות בטווח הזמן הנבחר.
- **סימון חזותי ביומן התנועות (Ledger Breach Badge):** הצגת תגית אזהרה מיוחדת (`חריגה בקטגוריה`) לצד תנועות השייכות לקטגוריה החורגת מהתקרה בטווח הפעיל.
 
##### 6. אייקון התראות עליון ומונה חריגות פעיל (FR-NOTIF-BELL)
- **מיקום קבוע בשורה העליונה:** אייקון פעמון התראות ממוקם בשורה העליונה (Top Navigation Bar) באופן מובהק משמאל לכפתור הפרופיל, הן במסכי מחשב (Desktop) והן במסכי טלפון נייד (Mobile).
- **מונה חריגות בזמן אמת (Active Overrun Counter Badge):**
  - תגית מונה זוהרת בצבע אדום ניאון מעל הפעמון המציגה את כמות תקרות התקציב שנחצו בפועל בכל טווחי הזמן המנוטרים (יומי, שבועי, חודשי, טווח מותאם).
  - המונה מתעדכן אוטומטית בכל רישום, עריכה או מחיקה של תנועה וכן בשינוי הגדרות תקרות.
  - כאשר אין חריגות פעילות, התגית מוסתרת כדי לשמור על ממשק נקי ורגוע.
- **חלונית פופאבר אינטראקטיבית (Notification Dropdown Popover):**
  - לחיצה על הפעמון פותחת תפריט נגלל מעוצב (Glassmorphism) עם פירוט כל החריגות הפעילות (שם קטגוריה, טווח זמן, סך הוצאה, תקרה וסכום החריגה המדויק).
  - מצב ריק (Empty State): במקרה שאין חריגות, מוצג חיווי ירוק מעודד: *"אין חריגות פעילות - הכל בשליטה!"*.
- **ניווט ישיר בלחיצה (One-Click Period Jump):** לחיצה על פריט חריגה מתוך רשימת ההתראות מעבירה באופן מיידי ואוטומטי את תצוגת האפליקציה לתקופה הרלוונטית (למשל: קפיצה למבט שבועי או יומי), מעדכנת את הגרפים ומד הצעדים, וסוגרת את החלונית.

#### 5.2.2 הוספה ומחיקה של קטגוריות מותאמות אישית (FR-CUSTOM-CATEGORIES)

##### 1. רציונל וערך למשתמש
- מתן גמישות מלאה למשתמש ליצור קטגוריות הוצאה ייעודיות המותאמות לסגנון חייו האישי (כגון: "גיימינג", "חיות מחמד", "לימודים", "קפה ומאפה", "תחביבים", "טיולים").
- יצירת הקטגוריה מתבצעת ישירות מתוך מודאל הגדרת התקרות, כך שמיד עם הגדרתה המשתמש מונחה לקבוע עבורה יעד תקציב (יומי, שבועי או חודשי).

##### 2. תהליך יצירת קטגוריה חדשה (Creation Workflow)
- **כפתור טריגר ייעודי:** כפתור בולט בעיצוב Cyber Neon `＋ הוספת קטגוריה חדשה` המוצב בראש מקטע תקרות הקטגוריה במודאל התקרות (`#capsModal`).
- **פאנל יצירה נפתח (Collapsible Panel):**
  - **שם הקטגוריה:** שדה טקסט עם הגבלת אורך (עד 25 תווים) ובדיקת כפילויות מול שמות קיימים במערכת (למניעת יצירת קטגוריה זהה).
  - **בורר אימוג'י מהיר ואישי:** גריד מהיר של 16 סמלים פופולריים (🎮, 🐾, 📚, ☕, 🎨, 🎵, 💻, ✈️ ועוד) לצד שדה להזנת כל אימוג'י או תו גרפי חופשי מהמקלדת.
  - **בורר צבעי ניאון:** פלטת 8 צבעי ניאון ייחודיים לזיהוי ברור בגרפים ובטבלאות (`#00F5D4`, `#10B981`, `#38BDF8`, `#EC4899`, `#A855F7`, `#F59E0B`, `#EF4444`, `#6366F1`).
  - **אישור ושמירה:** לחיצה על "צור קטגוריה ✓" (או הקשת Enter) יוצרת את הקטגוריה, מפיקה מזהה ייחודי (`cust_...`), שומרת אותה מקומית ב-`localStorage` וב-Firestore, סוגרת את הפאנל, ופותחת אוטומטית את כרטיסיית התקרה החדשה עם פוקוס להזנת תקרות.
  - **משוב קולי:** השמעת צליל Mario Coin קופצני.

##### 3. מחיקת קטגוריה ומיגרציה בטוחה של תנועות (Safe Deletion & Migration)
- **כפתור מחיקה (🗑️):** מופיע בכותרת הכרטיסייה עבור קטגוריות מותאמות אישית בלבד (`isCustom: true`).
- **אישור מחיקה חכם ומניעת אובדן מידע:**
  - המערכת סורקת וסופרת בזמן אמת את כמות התנועות שמשויכות לאותה קטגוריה.
  - אם קיימות תנועות, מוקפצת הודעת אישור ברורה המציינת את כמות התנועות:
    > *"האם למחוק את הקטגוריה [שם]? קיימות X תנועות המשויכות אליה, והן יועברו אוטומטית לקטגוריה 'הוצאות שונות'."*
  - באישור המשתמש:
    1. כל התנועות הקיימות מעודכנות אוטומטית לקטגוריה `other_exp` ("הוצאות שונות" 📦) ונשמרות במקביל מקומית ובענן Firestore.
    2. הגדרות התקרה של הקטגוריה מנוקות מ-`categoryCaps`.
    3. הקטגוריה נמחקת מהמערכת וממסמך הקטגוריות בענן (`users/{uid}/settings/customCategories`).
    4. הממשק מתרענן מיידית והתקציב הכולל נשמר ללא שינוי וללא אובדן נתונים היסטוריים.
    5. מושמע צליל Mario Jump.

##### 4. שילוב מלא בחישובי תקרות, הוצאות ו-BI
- כל תנועה בקטגוריה החדשה מחושבת במלואה כהוצאה תקפה בסך ההוצאות בלוח המחוונים, ביתרה שנותרה ובאחוז הניצול.
- הקטגוריה מקבלת שורה עצמאית בטבלת פילוח הקטגוריות מתחת לגרף, עם השוואה לתקרה שלה וחיווי חריגה (`row-breach`).
- גרפי ההוצאות (עמודות/דונאט) מציגים את הקטגוריה בצבע, בסמל ובסכום שלה.
- חריגה מתקרת הקטגוריה מפעילה את באנר האזהרה ואת פעמון ההתראות העליון.

### 5.3 מנוע תנועות פיננסיות (FR-TX)
- **FR-TX-1 (הוספת תנועה חדשה):** חלונית מהירה להזנת:
  - סכום (₪)
  - סוג תנועה: הוצאה (`expense`) או הכנסה (`income`)
  - קטגוריה (מתחלפת אוטומטית לפי סוג התנועה – קטגוריות הוצאה מול הכנסה)
  - תאריך ושעה (ברירת מחדל: הרגע הנוכחי)
  - הערה חופשית / שם בית העסק
- **FR-TX-2 (מניעת כפילויות):** אכיפת מזהה ייחודי חד-ערכי (UUID) לכל תנועה, מניעת כפילויות ברישום מקומי ובענן.
- **FR-TX-3 (מחיקת תנועה מהירה):** כפתור מחיקה ישיר לצד כל שורה ברשימה עם עדכון תקציב חי ומיידי.
- **FR-TX-4 (לשוניות סינון ומונים):**
  - לשוניות "הכל", "הוצאות", "הכנסות" עם מונה פריטים מובנה ישירות על גבי הכפתור (לדוגמה: `הוצאות (18)`).
  - הסרת תווית ה-₪ הצפופה מרשומות בודדות כדי למנוע חפיפת טקסטים במסכים קטנים.
  - הצגת בורר טווח תאריכים מותאם אישית אך ורק כאשר הלשונית "טווח תאריכים" נבחרת.

### 5.4 מד הצעדים הפיננסי (FR-HERO)
- **FR-HERO-1 (טבעת התקדמות SVG):** מד מעגלי בדיוק גבוה ($r = 90$, היקף כ-565.48 פיקסלים) עם אנימציית מילוי חלקה.
- **FR-HERO-2 (מעבר תקופות):** מעבר בלחיצה אחת בין מבט יומי, שבועי, חודשי וטווח תאריכים.
- **FR-HERO-3 (כרטיסיות מדדים מרכזיות):**
  - נוצל (סך ההוצאות)
  - תקרה מוגדרת
  - יתרה נותרת
  - הכנסות
  - מאזן נטו (הכנסות פחות הוצאות)

### 5.5 אנליטיקה וגרפים חכמים (FR-CHART)
- **FR-CHART-1 (מבט יומי):** גרף עמודות אופקי המציג את פילוח ההוצאות של היום לפי קטגוריות ואחוזים.
- **FR-CHART-2 (מבט שבועי):** גרף עמודות אנכי של 7 ימי השבוע (ראשון–שבת) עם קו מקווקו של יעד התקרה היומית.
- **FR-CHART-3 (גרף חודשי משולב עמודות וקו עם ציר Y כפול):**
  - **ציר Y שמאלי (טורקיז):** מוקדש להוצאה המצטברת מתחילת החודש ולקו האדום המקווקו של התקרה החודשית (באלפי שקלים).
  - **ציר Y ימני (סגול ניאון):** מוקדש להוצאות היומיות הבודדות עבור כל יום בחודש (בעשרות/מאות שקלים).
  - **צבעוניות דינמית לעמודות:** עמודה סגולה רגילה, כתומה בימים שהגיעו ל-80% מהתקרה היומית, ואדומה בחריגה מהתקרה היומית.
  - **חלונית מידע (Tooltip):** מציגה את "יום X בחודש", את ההוצאה היומית ואת הסכום המצטבר. ימים עתידיים נותרים ריקים ונקיים.
- **FR-CHART-4 (מבט טווח תאריכים):** התפלגות קטגוריות מותאמת אישית לטווח ימים שנבחר.
- **FR-CHART-5 (טבלת פילוח תקרות והוצאות לפי קטגוריה מתחת לגרף - FR-CAT-BREAKDOWN-TABLE):**
  - **מיקום ופריסה:** פאנל טבלאי ייעודי המוטמע ישירות מתחת לקנבס הגרף ומעל ליומן התנועות (`txSection`), בעיצוב Dark Glassmorphism תואם.
  - **הצגה מותנית בסוג הסינון:**
    - מוצג אך ורק כאשר המשתמש בוחר בסינון תקופתי מוגדר: **יומי (`daily`)**, **שבועי (`weekly`)**, או **חודשי (`monthly`)**.
    - מוסתר לחלוטין כאשר נבחר סינון לפי **טווח תאריכים (`custom`)**, לשמירה על ממשק ממוקד וללא עודף מידע שאינו מוגדר לו תקציב קשיח.
  - **סינון קטגוריות פעילות בלבד:** הטבלה מציגה אך ורק קטגוריות שהוגדרו או נרשמו בהן הוצאות בפועל בתקופה הנבחרת (`סך הוצאה > 0`), ובכך נמנעת הצפת הטבלה בשורות ריקות.
  - **מבנה נתונים ועמודות הטבלה:**
    1. *קטגוריה:* אייקון גרפי, שם הקטגוריה בעברית ותגית זיהוי.
    2. *תקרה לתקופה (₪):* סכום התקרה הרלוונטי לתקופה הנבחרת (יומי, שבועי או חודשי), או סימון קו (`-`) לקטגוריה ללא תקרה פרטנית.
    3. *הוצאות בפועל (₪):* סך כל ההוצאות שבוצעו בקטגוריה זו בטווח התאריכים הנבחר.
    4. *% ניצול מהתקרה ופס התקדמות גרפי:*
       - הצגת אחוז הניצול המדויק ($\frac{\text{הוצאה}}{\text{תקרה}} \times 100$).
       - פס התקדמות מיניאטורי זוהר ב-3 מדרגות צבע: בטוח (טורקיז ניאון מתחת ל-80%), אזהרה (כתום 80%-100%), וחריגה (אדום בוהק מעל 100% בצירוף תגית אזהרה מודגשת `חריגה!`).
  - **סנכרון חי ועדכון מיידי:** הטבלה מתעדכנת בזמן אמת בכל הוספה, מחיקה או שינוי של תנועה או תקרה.

### 5.6 מנוע סאונד רטרו מסונתז (FR-SOUND)
- **FR-SOUND-1 (אפס תלות בקבצי שמע):** ייצור צלילי 8-bit בזמן אמת באמצעות Web Audio API (מתנדים גלי ריבוע ומשולש).
- **FR-SOUND-2 (בנק צלילי Super Mario):**
  - *קפיצת מריו (Mario Jump):* בלחיצה על כפתורים מרכזיים.
  - *מטבע מריו (Mario Coin):* בעת שמירת תנועה בהצלחה.
  - *פטריה / 1-UP:* בהשלמת הגדרת תקציב או אירוע מוצלח.
  - *בלימה / אזהרה (Mario Bump):* בהגעה לטווח אזהרה (80%).
  - *סיום משחק (Mario Game Over):* בחריגה מעבר לתקרה המותרת.
- **FR-SOUND-3 (מתג השתקה):** אפשרות כיבוי והפעלה של הסאונד מהגדרות המערכת.

### 5.7 מנוע Finance BI ותובנות חכמות לצעירים (FR-BI)

#### 1. חזון ושפת המוצר (Tone & Young Audience Focus)
- **התאמה מלאה לדור הצעיר (גילאי 15–30):** מערכת ה-BI תוכננה מתוך הבנה שצעירים נרתעים מגרפים יבשים וממינוחים בנקאיים כבדים.
- **שפה קלילה וסלנג חיובי ומעצים:** החלפת מושגים חשבונאיים כבדים (כגון "תזרים תפעולי", "גרעון אקטוארי") בביטויים קלילים, ישירים ומעודדים (כגון: "סגרת שבוע כמו אלוף! 👑", "וולט וורייר 🍔", "הדופק שלך בשיא 🚀").
- **חוויית מובייל-פירסט (Mobile-First Ergonomics):** כפתורי גישה ייעודיים בסרגל הניווט העליון, טאפ נוח באגודל ואנימציות קצביות.
- החלוקה לשלושה שלבי עומק (Phases):

#### 2. שלב 1: נאגטס פיננסיים יומיים (Pulse Nuggets - FR-BI-NUGGETS)
- **כרטיסיית מיקרו-תובנה צפה (Nugget Card):** משובצת באופן טבעי במרכז לוח המחוונים הראשי (`#pulseNuggetsSection`).
- **אלגוריתם תובנות מבוסס כללים חכמים בזמן אמת:**
  - *מעקב רצף חיובי (Savings Streak):* זיהוי ימים רצופים ללא חריגה ("3 ימים רצופים מתחת לתקרה! ממשיכים ככה 🔥").
  - *קצב שריפה יומי (Daily Burn Rate):* התראה עדינה ומעצימה כשקצב ההוצאה היומי מתקרב לגבול העליון.
  - *ניטור הוצאות מסעדות ומשלוחים:* זיהוי נתח הוצאה גבוה של משלוחי אוכל ("וולט לוקח נתח רציני השבוע – אולי נבשל משהו טעים בבית? 🍔").
  - *עידוד סוף שבוע:* סיכום שבועי קצר ומחמיא.
- **אינטראקטיביות ודפדוף:** כפתור ריענון/דפדוף מהיר (🔄) המאפשר למשתמש לעבור בין תובנות שונות בלחיצה אחת.

#### 3. שלב 2: מעבדת הדופק הפיננסי (Pulse Lab - FR-BI-LAB)
- **חלונית מעבדה ייעודית (Pulse Lab Modal):** נפתחת בלחיצה על כפתור "Lab" בסרגל העליון ומציגה ניתוח עומק של הרגלי הצריכה והתזרים.
- **4 מדדי מפתח מרכזיים (Key Performance Indicators):**
  1. 🚀 **תחזית סוף חודש (Projected Month-End Spend):** חישוב אקסטרפולציה של קצב ההוצאה היומי הממוצע כפול מספר ימי החודש, כדי להתריע מראש האם המשתמש צפוי לעמוד ביעד החודשי או לחרוג ממנו.
  2. 💎 **נשמר בכיס מההכנסות (Savings / Cash Kept Rate):** חישוב אחוז החיסכון הריאלי מתוך ההכנסות ($\frac{\text{מאזן נטו}}{\text{סך הכנסות}} \times 100$).
  3. 🔥 **היום הכי יקר בשבוע (Peak Spend Day):** איתור היום בשבוע שבו המשתמש מוציא את הסכומים הגבוהים ביותר בממוצע (למשל: ימי חמישי/שישי).
  4. ⚡ **קצב שריפה יומי מול יעד (Daily Burn Rate vs Target):** השוואה ישירה בין ממוצע ההוצאה היומי בפועל לבין תקרת התקציב היומית שהוגדרה.
- **מפת החום של השבוע (Weekly Vibe Heatmap):** רשת של 7 ימי השבוע עם דרגות צבע (רגוע, פושר, חם, רותח) הממחישה את הדופק השבועי במבט ויזואלי אחד.
- **בולעני הכסף (Top Expense Eaters):** דירוג 3 קטגוריות ההוצאה המובילות עם חישוב נתח האחוזים שלהן מכלל ההוצאות.
- **המלצות אקשן מיידיות (Quick Action Tips):** כרטיסיות המלצה פרקטיות וקצרות ליישום מיידי לצמצום הוצאות עודפות.

#### 4. שלב 3: סיכום חודשי ויראלי (Pulse Wrapped - FR-BI-WRAPPED)
- **חוויית סטוריז אינטראקטיבית (Stories-Like UI):** חוויה ויזואלית וקולית מלאה בהשראת Spotify Wrapped, המותאמת במיוחד למובייל (ניווט בלחיצה בימין/שמאל המסך, סרגל התקדמות עליון, אנימציות וקונפטי).
- **באנר הזמנה מונפש (Dashboard Invitation Banner):** מופיע אוטומטית במסך הראשי כאשר נצבר מידע חודשי מספק ומזמין את המשתמש לצפות בסיכום שלו.
- **שקופיות הסטורי המותאמות אישית:**
  - *שקופית 1 (סך ההוצאה):* המספר הגדול של החודש, עם השוואה ליעד.
  - *שקופית 2 (הקטגוריה השלטת):* הקטגוריה ששלטה בתקציב עם האייקון, הצבע וסך השקלים.
  - *שקופית 3 (יום השיא):* היום הספציפי שבו יצא הכי הרבה כסף והתנועה הבולטת באותו יום.
  - *שקופית 4 (מדד ה-Pulse Score):* ציון משוקלל (0–100) המשקלל עמידה בתקרות, ימי חיסכון ושיעור הוצאות.
  - *שקופית 5 (התואר והפרסונה הפיננסית):* הכרזה על הפרופיל החודשי: "מאסטר השליטה 👑", "וולט וורייר 🍔", "השורד החכם 🛡️", "פזרן ספונטני 💸", "מלך החיסכון 💎".
- **שיתוף ויראלי ברשתות החברתיות (Social Sharing):** כפתור שיתוף המשתמש ב-Web Share API לפרסום ישיר של תעודת התואר בוואטסאפ, אינסטגרם סטוריז וטיקטוק.

## 6. דרישות לא-פונקציונליות (Non-Functional Requirements)

### 6.1 ביצועים ומהירות תגובה (Performance)
- **זמן טעינה ראשוני:** פחות מ-1.5 שניות ברשתות סלולריות 4G.
- **זמן תגובת ממשק (Latency):** מתחת ל-50 מילי-שניות עבור פעולות סינון, מעבר לשוניות ופתיחת מודאלים.
- **גודל חבילת קוד (Bundle Size):** דחיסת Gzip מתחת ל-260KB באמצעות Vite.

### 6.2 ממשק משתמש ונגישות (UI/UX)
- **RTL מובנה ומלא:** תמיכה מלאה בכיווניות מימין-לשמאל בשפה העברית.
- **טיפוגרפיה איכותית:** שימוש בגופני גוגל מותאמים (`Heebo` לעברית, `JetBrains Mono` למספרים ומטבעות, `Outfit` למותג וללוגו).
- **עיצוב Dark Glassmorphism:** ערכת צבעים כהה יוקרתית עם שקיפויות זכוכית, זוהר ניאון וטשטושי רקע (`backdrop-filter`).
- **ארגונומיה במובייל:** דחיסת כותרת העליונה ל-2 שורות בלבד במסכי סלולר, אזורי לחיצה מרווחים (מעל 44px) ונגישות אגודל מיטבית.

### 6.3 אבטחת מידע ופרטיות (Security)
- **בידוד נתונים לפי משתמש:** כל המידע שמור תחת המסלול המבודד `users/{userId}/*`.
- **חוקי אבטחה בשרת (Firestore Security Rules):**
  ```javascript
  rules_version = '2';
  service cloud.firestore {
    match /databases/{database}/documents {
      match /users/{userId}/{document=**} {
        allow read, write: if request.auth != null && request.auth.uid == userId;
      }
    }
  }
  ```
- **אפס דליפת מידע בין משתמשים:** אין שאילתות כלליות חוצות-משתמשים.

### 6.4 שרידות ועבודה במצב מנותק וסנכרון ברשת (Offline Resilience & Sync-On-Connect)
- **IndexedDB Multi-Tab Persistent Local Cache:**
  - אתחול מסד הנתונים של Firestore באמצעות `initializeFirestore` עם `persistentLocalCache` ו-`persistentMultipleTabManager()`.
  - תור הכתיבה ונתוני המשתמש נשמרים ישירות ב-IndexedDB של המכשיר.
  - פעולות והזנות שבוצעו במצב מנותק שורדות סגירת טאב, רענון דפדפן וסגירת אפליקציה, ומסונכרנות אוטומטית ברגע שהרשת מתחברת מחדש.
- **מנגנון מיזוג דו-כיווני חסין דריסות (Two-Way Offline Merge):**
  - בעת האזנה לנתוני ענן (`subscribeToUserTransactions`), המערכת משווה בין הנתונים המקומיים לנתוני הענן ומזהה תנועות שנוצרו באופליין וטרם עלו לשרת.
  - תנועות מקומיות אלו ממוזגות לרשימה הפעילה ומועלות מיד ל-Firestore. אין כל חשש לדריסה או אובדן מידע מקומי.
- **זיהוי קישוריות רשת והתראות Toast צפות (Cyber Neon Floating Toasts):**
  - האזנה חיה לאירועי `online` ו-`offline` של הדפדפן.
  - הקפצת הודעות Toast מעוצבות בסגנון Dark Glassmorphism עם הילה זוהרת בתחתית המסך:
    - בעת ניתוק: *"📴 עברת למצב לא מקוון (Offline). כל הנתונים נשמרים בבטחה."*
    - בעת חיבור מחדש: *"📶 החיבור לרשת חזר – מסנכרן נתונים לענן..."*
  - ביצוע סנכרון יזום של כל התנועות המקומיות עם חזרת התקשורת.

## 8. מודל הנתונים וקטלוג קטגוריות

### 8.1 רשומת תנועה (`Transaction` ב-`src/types.ts`)
```typescript
export type TransactionType = 'expense' | 'income';

export interface Transaction {
  id: string;             // מזהה חד-ערכי ייחודי (UUID)
  type: TransactionType;  // 'expense' (הוצאה) או 'income' (הכנסה)
  amount: number;         // סכום חיובי בשקלים (₪)
  category: string;       // מזהה קטגוריה (לדוגמה 'food', 'salary', 'cust_...')
  date: string;           // תאריך ושעה בפורמט ISO
  note?: string;          // הערה חופשית / שם בית העסק
  receiptUrl?: string;    // קישור עתידי לתמונת קבלה בענן
  createdAt: number;      // חותמת זמן במילי-שניות
}
```

### 8.2 תקרות תקציב (`BudgetCaps`)
```typescript
export interface BudgetCaps {

  monthly: number;                                    // תקרה חודשית בש"ח (למשל 10,000)
  categoryCaps?: Record<string, Partial<BudgetCaps>>; // תקרות פרטניות לפי מזהה קטגוריה
}
```

```typescript
export interface CategoryInfo {
```

- **קטגוריות הוצאה מובנות:**
  - 🍔 מזון ומסעדות (`food`)
  - 🚗 תחבורה ודלק (`transport`)
  - ⚡ חשבונות וחשמל (`bills`)
  - 🛍️ קניות וביגוד (`shopping`)
  - 🎉 בילויים ופנאי (`entertainment`)
  - 💊 בריאות וכושר (`health`)
